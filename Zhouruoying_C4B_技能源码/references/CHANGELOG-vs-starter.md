# CHANGELOG — Zhouruoying_C4B_wechat-publisher vs. 官方 starter kit

本文件回答一个具体问题：**相对 Elite20 提供的 starter kit，我到底改了什么、为什么改。**
每一条都对应一次真实运行的失败或一次实测缺口，并指明验证方式。

- starter 原始：`SKILL.md` 4,776 B；`scripts/convert_to_wechat.py` 11,800 B / 383 行
- 我的版本：`SKILL.md` + `scripts/convert_to_wechat.py`（1,219 行）+ `references/` × 3 + `examples/`
- 验证方式：`python3 -B scripts/convert_to_wechat.py --self-test`（8 用例，全绿 exit=0）

## 一、修复（starter 跑起来就会暴露的问题）

| # | 现象 | 定位 | 处置 | 验证 |
|---|------|------|------|------|
| B1 | **空输入静默成功**：给一个空 `.md`，starter 退出码 0 并写出空 HTML | 无内容校验 | 空/纯空白正文直接报错并非零退出 | 反例A |
| B2 | **非 UTF-8 崩溃**：GBK 写的 `.md` 抛 `UnicodeDecodeError`，用户只看到回溯 | 硬编码 `encoding="utf-8"` | 按 `utf-8 → utf-8-sig → gbk → gb18030 → big5` 依次试解，失败才报错 | 反例B |
| B3 | **净化是死代码**：`ALLOWED_CSS` 定义了但未被调用，禁用属性照样留在输出里 | 缺真正的过滤循环 | 实现按元素 `style` 逐条过滤，命中禁用项即剔除 | 反例C + 自检G |
| B4 | **移除标签时丢嵌套行内**：把 `<div>...</div>` 降级为 `<p>` 时，里面的 `<strong>` 一起没了 | 用 `get_text()` 取纯文本 | 改为「保留子节点结构、只换外壳」 | 反例C |
| B5 | **代码块换行被吃掉**：`<pre><code>` 转 `<p>` 后所有换行消失，代码挤成一行 | 直接塞文本 | 每个逻辑行转显式 `<br>` 并用 `&nbsp;` 保住缩进，保留语言角标 | 正例 + 反例C |
| B6 | **图片撑破手机屏**：`<img>` 无宽度约束，宽图溢出 | 样式缺省 | 补 `max-width: 100%; height: auto; display: block` | 反例E |
| B7 | **首次运行必崩**：`install_dependencies()` 装完依赖却从未真正 import，Markdown 管线报 `NameError: name 'markdown' is not defined` | 依赖探测与实际使用脱节 | 安装后显式导入；`python-docx` 改为可选导入，没装也能跑 Markdown | 自检 8/8 由红转绿 |

> B7 是**我自己引入然后修掉的**：一开始我只跑通了 starter 的 CLI 帮助，直到端到端跑真实文章才
> 暴露 4 个用例连红。这条留在这里，是因为「装完依赖不等于导入依赖」正是典型的自检盲区。

## 二、新增能力（starter 没有，为公众号真实使用补齐）

| 能力 | 说明 | 为什么需要 |
|------|------|------------|
| **4 套主题** `--theme` | default / blue / warm / minimal，样式全部由调色板推导 | 技术文、叙事文、观点文需要不同气质，改一组色值即可换肤 |
| **Callout 高亮框** | `> [!TIP]` 等 4 类（知识点/小技巧/注意/补充），带图标与中文别名 | 公众号长文靠视觉锚点提高留存；颜色固定不随主题，形成稳定语义 |
| **自动目录** `--toc` | 依据 h2/h3 生成带序号的导航清单 | 长文必备；微信内不能跳转锚点，目录靠「位置记忆」发挥作用 |
| **中英混排优化** | 中英文/数字间自动加空格、半角标点转全角 | 中文排版最影响观感的一项，手工调最费时 |
| **页脚版权** `--footer-text` | 底部居中署名/来源 | 公众号文章的默认收尾 |
| **图片 base64 PNG 内联** | 本地图片转 `data:image/png;base64,...` | 直接复制进微信编辑器不丢图 |
| **SVG 主动拦截** | 检测到 SVG base64 或内联 `<svg>` 时警告 | 微信会静默丢 SVG，不拦就是「发出去才发现图没了」 |
| **自检套件** `--self-test` | 6 反例 + 1 正例，含「校验器自证」 | 让技能可被独立验证，而不是靠作者口头保证 |
| **运行报告** `--report` | 输出字数/图片数/违规项 JSON | 提交与复现都需要机器可读证据 |
| **YAML front matter** | `title/author/date/abstract` 可直接写在 md 头部 | 减少命令行参数，文章即配置 |

## 三、明确**未做**的事（边界）

- **不做发布**：技能只产出「可粘贴 HTML」，发布仍由人在公众号后台手动完成（平台限制，也是权限边界）。
- **不做图片美化/裁剪**：只做内联与尺寸约束，不代改内容。
- **不追新主题**：4 套覆盖主要文体，再多是维护负担；`wechat_styles.md` 已写明改配色只需动一组值。
- **不做 Word 深度支持**：`.docx` 走文本+基础样式提取，复杂 Word 版式（文本框/公式）不保证。
