公众号排版总跑版？我做了个「发之前先自检」的转换器

在 Markdown 里写得工工整整的一篇文章，复制进公众号编辑器，一贴进去就崩了：标题样式没了、代码块变成一堆小方块、图片裂成空白、表格直接错位。

这不是你的问题，是公众号编辑器的「口味」太窄。

公众号编辑器到底吃什么

先把心智模型摆正：公众号编辑器不是一个浏览器，它只认一个很窄的 HTML 子集。

  • ** 样式必须内联 **。它不认 class 和 id 选择器，所以你不能靠一份外部样式表统一样式，只能把样式一条条写进每个标签的 style 属性里。
  • ** 标签有白名单 **。能用的基本只有：p、h2、h3、ul、ol、li、span、img、a、table、tr、th、td、br。script、style、iframe、div、h1 一概不收。
  • ** 图片要内联 **。它只认 PNG / JPG / GIF 的 base64 内联图；外链图会被防盗链机制干掉，SVG 保存后直接丢图。

说白了，它要的是「内联、扁平、纯白名单」的内容。我们在网页世界里习惯的那套写法，在这里大部分是无效的。

这就是「排版总跑版」的根因——不是审美问题，是格式不对口。

我的做法：源文件进，能粘贴的 HTML 出

与其每次手工重排，不如把它做成一条流水线。我做了一个叫 wechat-publisher 的小工具，输入 Markdown、纯文本、HTML 或 Word，输出一段能 ** 直接粘进公众号编辑器 ** 的 HTML。

它做的核心动作就三件：

  1. 把 Markdown 转成 HTML，再把所有样式 ** 内联 ** 到每个标签上；
  2. 按白名单过滤标签和属性，把违规元素（script、div、外链样式）清掉或降级；
  3. 把本地图片读成 base64 内联进去，解决防盗链丢图的问题。

四个让我觉得「值回票价」的能力

  • ** 主题与配色系统 **：内置 default / blue / warm / minimal 四套配色，一条参数切换整篇的观感，不用改内容。
  • Callout 高亮框 ：用 > [!NOTE]、> [!WARNING] 这样的写法，自动渲染成带图标和底色的提示框，还支持「知识点 / 小技巧 / 警告 / 补充说明」这些中文别名。教程类文章特别受用。
  • ** 自动目录 **：根据标题层级自动生成带锚点的目录，长文不用手排。
  • ** 中英混排优化 ：自动在中文与英文、数字之间补上该有的间距，并把半角标点规范成中文标点——同时， 代码块被严格保护 **，不会被误伤。

真正的关键：它会自己「体检」

上面这些都是「锦上添花」。真正让我觉得这个工具靠谱的，是它在输出前会跑一遍 ** 自检 **。

它内置 9 条用例：1 条完整管线正例 + 8 条负例，覆盖空文件、GBK 编码输入、脏 HTML 净化、SVG 图拦截、本地图片内联成 base64、以及「data URI 的标签必须与真实字节一致」这类容易踩的坑。跑完直接告诉你 9/9 PASS 还是哪条转红。

更有意思的一点是： 校验器本身也在被测试 。用例里会人为注入一条违规，如果校验器抓不出来，就算失败。这样它就测的是真东西，而不是空跑。

这套自检让「发之前先知道会不会跑版」变成了可能——而不是发出去之后被读者截图告诉你图裂了。

一条我这次真正学到的东西

做这个工具的过程中，我对「什么算完成」的判断改了。

AI 很擅长说「已完成」「已通过」。但你把它的话当结论，就会踩坑：它可能只是没报错，而不是真的做对了。所以我现在只认三样东西—— 可复现的退出码、留在磁盘上的日志、被独立复算过的字节 。

工具能不能用、标签和字节对不对得上，都要跑一次、看一眼，才算数。这条规则后来贯穿了我做这个工具的全过程：每一次改动，都有一条例例在等着它。

想试试的话

工具是零依赖的 Python 脚本，最终产物是一个 .skill 技能包，也可以直接当命令行用：

python3 convert_to_wechat.py 你的文章.md -o 输出.html --theme blue
python3 convert_to_wechat.py --self-test # 跑 9 条正反例自检

如果你也受够了「贴进公众号就崩」，不妨试试这种「源文件进、HTML 出」的思路。排版本该是机器干的活，人的精力应该留给内容本身。
